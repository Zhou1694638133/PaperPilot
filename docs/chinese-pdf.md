# 中文论文 PDF

在论文详情的“双语对照”下载区，先点“生成中文版 PDF”。任务完成后同一位置显示“下载中文版 PDF”。原有双语 PDF 与 Markdown 下载保留；下载使用普通附件链接，兼容 IDM。

中文版采用黑色宋体、Letter 纸、跟随原文的单栏或双栏布局。页眉不重复显示章节名，页码置于页脚；正文标题保留，项目列表改为无圆点、首行缩进的独立段落。标题、章节、正文、图注、表格说明和算法指令使用中文；保留作者姓名、必要缩写、代码标识、原图中的文字以及原文参考文献。原图以 PDF/PNG/JPEG 资源嵌入，算法与公式正常排版。应用状态、QA 提示、证据位置和研究说明只在工作台显示，不进入论文 PDF。

## 安装和启动

已安装的项目可直接启动 API 和 worker。新机器在项目目录执行：

```powershell
.\scripts\install-tectonic.ps1
.\scripts\start.ps1 api
# 另开终端
.\scripts\start.ps1 worker
```

安装脚本固定官方 Tectonic 0.17.0 Windows x64 版本，校验 SHA-256，写入 `tools/tectonic/`，不修改全局 PATH。首次编译会下载需要的 TeX 宏包。使用 Windows 自带 SimSun；缺少字体或网络时任务会明确失败。没有新增 Python/npm 依赖，不修改已有锁文件。

## 数据与恢复

- 输入必须是当前版本已完成的 LaTeX 全文翻译。源 hash 不一致、缺图或缺少参考文献源文件时不发布残缺文件。
- 正文使用原 `translation_chunks`，不重新翻译、不改写检查点。新增的文字片段写入 `analysis_chunks`。
- 新版式任务可以复用同一个原翻译任务、同术语表、同模型/服务地址的补译检查点。
- 模型调用、编译、失败与取消使用原有独立 worker 和 SSE。连接断开后任务持续运行；任务中心可恢复失败任务。模型结果不确定时沿用重复计费确认规则。
- 编译材料位于后端数据目录的 `chinese-pdf/<job-id>/`。成功后通过 `GET /api/jobs/<job-id>/chinese.pdf` 下载，未完成返回 409，产物丢失返回 410。
- 未配置模型时不能补译新图表文字，但已生成的中文版和原双语文件可继续下载。

## 支持边界

目前支持常用论文 LaTeX 环境与简单纯文本宏。特殊自定义命令会明确报错，不猜测含义；只包含 PDF 文本提取的论文尚不支持保证图表完整的中文版导出。原图内部的英文标注按原图保留，不进行破坏性改图。黑色要求用于新排版的文字，原图颜色保持原样。

API 输入输出 schema 可在 `/api/skills` 查看。`skills/chinese_pdf/` 是规范，后端 allowlist runner 执行实际任务。

版式优先通过原 PDF 的多页正文行布局识别，跳过首页标题/摘要；正文证据不足时使用 LaTeX 显式栏数设置。无法确认或检测到混合栏数时明确报错，不默认强制双栏。栏数证据记录在任务结果的 `column_layout`，不写入论文正文。中文版按译文长度自然分页，不承诺与英文逐页等长。

固定模板已存入 `skills/chinese_pdf/templates/single-column.tex` 与 `two-column.tex`，版式版本为 1.0.7，注册表记录各自 SHA-256。译文下载统一命名为 `原论文标题翻译版.pdf` / `.md`，采用原始英文标题；禁用字符替换、超长标题安全截断。由后端响应头提供名称，前端不覆盖，已完成的译文无需重新生成。

## 中英文对照 PDF

双语正文采用中文黑色宋体 12 pt、英文 Times New Roman 11.5 pt，20 pt 行距、首行缩进 24 pt，页脚只显示页码。全文 LaTeX 导出由 `backend/app/bilingual_pdf.py` 复用固定单栏/双栏模板，原图、数学公式、算法和表格正常排版；中英文逐段对照，图表共用。过宽表格等比缩放。原图内部文字和参考文献保留原文，不添加应用说明。

仅复用既有译文检查点、标题和图注缓存，不调用模型；已有完整译文重新下载即可生效。首次编译后缓存，原生下载支持 Range，兼容 IDM。自然分页不保证原文页数。缺少支持的源文件时，摘要/PDF 文本翻译使用 `pdf_export.py` 的字体 profile，不能保证原图与数学版式。样式规范见 `skills/paper_translator/SKILL.md` 与 `templates/bilingual-style.json`。


## ICML 模板兼容（1.0.8）

ICML 作者符号、作者列表、单位、通讯作者和关键词先按原文解析成固定模板内容；原会议宏不进入编译器。原文显式附录单栏切换保留。数学符号和受限编号设置已适配；任意宏重定义仍拒绝。数值表格列转换仅改变对齐，不改变表内数值；代码按字面内容保留，跨段代码示例不发送给补译模型。

正文与成功补译缓存继续复用。整篇排版块、图像资源和参考文献在补译调用前统一核查，避免付费补译后才逐个发现不支持的模板命令。

零模型结构编译复现：

```powershell
.\backend\.venv\Scripts\python.exe scripts/verify_pdf_preflight.py <中文排版任务编号>
```

诊断产物在 `output/validation/chinese-icml-preflight`，保留尚未补译的原文标题和图注，仅用于结构检查，不能作为全中文最终成品。本次实际论文检查覆盖 278 个排版单元、30 个原图资源；完成编译且无缺字、未解析引用和溢出警告。相关单元与中文/双语排版回归 41 项通过。

## 模型正常但任务显示连接失败 / 继续按钮禁用

失败提示属于上次执行记录，模型恢复可用后任务不会自动重发请求。旧实现把自动恢复的三次上限也用于用户手动继续，导致按钮被锁住；现已分离。手动继续不限制累计次数、保留尝试历史；自动租约恢复仍最多三次；请求结果不确定时仍须确认可能重复计费。

模型连接错误现在区分 DNS、TLS 证书、TLS 握手、连接被拒绝、连接超时和代理连接失败，错误输出不包含原始异常消息、凭据或代理账号。可选 `LLM_TRUST_ENV=false` 禁止继承环境代理及证书环境设置，默认仍为 true，本次没有修改用户网络配置。

本次独立后端进程和用户正在运行的 API `/api/model-config/test` 均完成真实 JSON 生成测试；模型列表经环境代理和直连均 HTTP 200。不能由历史笼统错误反推当时一定是服务故障。

更新代码后须重启 API 和 worker，刷新页面再从原任务继续；旧 PyCharm 进程不会自动加载代码修复。成功检查点不需要删除，模型配置也无需重新填写。


## 表格线参数保护与旧缓存修复

根因：补译分词仅保护 `cmidrule` 命令名，没有保护 `(lr)` 裁边选项，模型将其翻译成“学习率”，最终 TeX 无法解析。现在整个命令（含可选线宽、裁边和列范围）作为不可翻译单元保护。

中文和双语排版读取旧补译缓存时，以原文恢复这类参数；只有命令数量、顺序和列范围全部一致且参数边界可识别时才修复。不修改正文、表格数字、原始翻译或补译缓存，不重新调用模型。命令缺失、多出、范围改动或混入其他命令时明确拒绝。

新增回归覆盖普通及带尺寸的裁边选项、旧中文误译恢复、正文“学习率”保留、数量/范围变化拒绝。相关测试共 37 项通过。正式恢复审计记录位于 `output/validation/table-rules/recovery.json`。

本次表格修复已用于正式任务，最终状态 succeeded / 100%。31 页中文版 PDF 已生成，30 个原图字节与原始资源一致；下载 HTTP 200，范围请求 HTTP 206。首页、第 9 页 SMACv2 表和第 31 页运行时间表渲染抽查通过，无编译溢出警告。模型调用为 0，正文和补译缓存哈希均未改变。修改涉及 `backend/app/pdf_compat.py`、`backend/app/chinese_pdf.py`、`backend/app/bilingual_pdf.py`、`backend/tests/test_pdf_compat.py` 及中文排版 Skill。
