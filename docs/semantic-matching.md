# 大模型语义匹配

## 使用方式

- 在研究偏好保存研究兴趣与模型配置。
- 在论文右侧“推荐依据”点击“评估当前论文语义匹配”，或在发现页点击“本页语义重排（最多 10 篇）”。批量处理当前排序的前 10 篇，其他论文可单篇评估。
- 默认检索、打开详情和刷新均不发起付费调用；上述按钮才提交模型任务。任务中心可以取消或手动重试，并下载语义分析 Markdown。
- 匹配排序使用已完成的语义分，未完成、失败、取消或无模型配置时使用关键词分；界面显示当前语义覆盖数量和每篇分数类型。CCF A 排序仍优先保留有来源依据的论文，新旧时间排序不受语义分影响。
- 关键词评分完整保留为独立对照；文库与详情会依据当前已保存兴趣重新计算关键词对照分，不覆盖历史检索记录。

## 评分与证据

输入包含标题、摘要和全部已保存研究兴趣，不向模型提供关键词分，避免其只复述关键词结果。模型为每个研究兴趣返回 0–100 的相关性分、中文理由和摘要证据编号；后端将编号还原为连续原文及字符位置，也兼容合法逐字引文。目标为 1–3 条，最多接受 8 条且逐条校验。

评分尺度：0 为无支持关系；1–29 为背景提及；30–59 为间接关联；60–79 为直接关联；80–100 为核心研究方向。服务端按“最高兴趣分 × 70% + 全部兴趣平均分 × 30%”聚合，以兼顾核心方向与覆盖面。该权重是可解释的初版排序策略，尚未通过用户标注集校准。

服务端拒绝遗漏、重复或改写研究兴趣，拒绝越界分数、无证据的正分及无法定位到摘要的引文。引文保存字符位置，页面可以展开查看。精确引文校验只能证明引文存在，不能证明模型的关联推断正确。模型输出不视为全文分析、质量概率、会议录用核实或实验复现结论。

## 执行、缓存与降级

新增可执行 Skill `semantic_ranker`，复用现有 Supervisor、独立 worker、SQLite 任务/产物与检查点；无需新增依赖、表或数据库迁移。

缓存身份包含论文 ID、版本、标题、摘要、模式、全部研究兴趣、模型名、服务地址和语义提示版本。兴趣顺序改变不重复计费；兴趣内容、论文或模型改变会产生新的评估。结果在重启后保留。重复提交不会自动重跑失败任务。

进度来自后端 SSE。超时且结果不明确时，进入“结果待确认”，回退关键词分，不自动重试付费请求。保存的模型结果检查点可复用。演示模式、无模型配置或空研究兴趣均不提交模型任务。

API：`POST /api/semantic/rank` 接收 `paper_ids`（1–10 个）和 `mode`；现有论文 API 返回 `semantic` 状态及结果。普通 `GET` 不创建模型任务。

- `npm.cmd run build` 通过（包含 TypeScript 检查）。浏览器验证 SSE 完成展示、逐兴趣理由/引文展开、关键词独立对照、列表语义分标记及已完成数量；390px / 320px 窄屏未发现语义面板横向溢出。

## 真实周报复查（2026-10-29）

提示版本升级为 semantic-v2，注册表与 skills/semantic_ranker/SKILL.md 同步。为 Agent 强化学习和大模型后训练提供明确边界，避免把“用 Agent 自动做后训练”混同为“通过 RL 训练 Agent 策略”。所有方向评分均基于摘要，不要求论文覆盖一个大方向中的所有子领域。

实测发现模型会将标题放入摘要证据，现优先使用仅从摘要生成的证据编号；标题或未知编号仍拒绝。另发现合法 4 条引文被旧 3 条上限拒绝，将硬上限改为 8 条；所有引用都必须通过验证，不截断隐藏非法引用。
